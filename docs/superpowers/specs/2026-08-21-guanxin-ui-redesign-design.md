# 观心 v2「观心识流」系统 UI 重设计规格

> 日期：2026-08-21
>
> 状态：设计已确认，待视觉稿与实施计划
>
> 范围：系统 UI、核心交互、图标、品牌标识、主题、响应式与可访问性

## 1. 目标与设计读法

观心 v2 是面向内部技术团队和外部合作方演示的 AI Agent 全栈系统。本次重设计的首要目标是增强演示感染力，让用户能够直观看到 Agent 如何理解意图、制定计划、调用工具、等待确认并恢复执行。同时，知识库、Skills、MCP、Agent 配置和 A2UI 等管理页面必须保持专业、清晰和可操作。

设计读法如下：将观心视为面向技术团队与合作方演示的 AI Agent 操作系统，采用深色优先、东方克制、实时智能的视觉语言，基于深度定制的 shadcn/Radix 组件体系。

本次属于视觉全面重构，保留现有业务能力、URL、主导航名称、表单数据结构和权限语义。不会为了视觉效果改变后端接口、工作流状态机或租户边界。

全局设计参数：

- `DESIGN_VARIANCE: 7`
- `MOTION_INTENSITY: 6`
- `VISUAL_DENSITY: 6`
- 视觉名称：「观心识流」
- 默认主题：跟随系统，首次演示推荐深色
- 唯一品牌强调色：玉青绿

## 2. 设计原则

### 2.1 Assistant 是主舞台

系统的核心叙事不再是六个平级功能页，而是围绕 Assistant 展示完整 Agent 行为。知识库、Skills、MCP、Agent 配置和 A2UI 是能力中心与系统配置，为 Assistant 的执行过程提供支撑。

### 2.2 状态必须可见且可信

界面必须区分规划中、执行中、等待输入、等待审批、结果不确定、已完成、失败和已取消。颜色、图标和动效只表达真实状态，不用作装饰。

### 2.3 演示感来自叙事，不来自堆叠特效

视觉冲击主要由信息层级、工作流轨迹、内容布局和状态转变产生。不使用常见 AI 紫色渐变、不在所有面板上使用玻璃材质、不添加无意义的呼吸动画和外发光。

### 2.4 管理页面优先可用性

`design-taste-frontend` 的高表现力原则仅用于品牌、登录、Assistant 主体验和关键状态过渡。密集配置、数据列表和多步骤产品操作仍遵循清晰、稳定、可访问的后台交互规则。

### 2.5 一个组件体系

继续使用项目已有的 shadcn/Radix 基础组件并进行系统化定制，不引入第二套完整设计系统。assistant-ui 与 AI SDK 的消息和数据部件继续作为对话层基础。

## 3. 信息架构

导航从六个平级入口调整为三级分组，但保留现有路由兼容。

### 3.1 工作台

- Assistant
- 最近会话
- 活动工作流

### 3.2 能力中心

- 知识库
- Skills
- MCP 服务

### 3.3 系统配置

- Agent 配置
- A2UI 实验室
- 用户与权限入口，仅管理员可见

现有 `/assistant`、`/knowledge`、`/skills`、`/agent`、`/mcp` 和 `/a2ui` 路由保持不变。若仍存在 `/chat` 兼容入口，应重定向到 `/assistant`，而不是继续形成第二套导航状态。

## 4. 全局应用框架

### 4.1 桌面布局

桌面端采用最多四个区域：

1. 72px 品牌功能轨道。
2. 240-280px 会话列表或模块内导航。
3. 自适应主工作区域。
4. 320px 按需出现的上下文检查器。

品牌轨道可以展开显示分组和文字标签。Assistant 使用第二列展示会话；管理页面可以将第二列用于筛选器、分类或模块内导航。上下文检查器默认关闭，点击来源、工具、工作流步骤、文档、Skill 或 Schema 时打开。

检查器出现时使用共享布局过渡，不让主内容发生突兀跳动。Assistant 主画布不设普通后台页面的固定最大宽度，但正文内容区限制在约 880px，图表和 A2UI 可以在主画布范围内适当加宽。

### 4.2 上下文工具栏

当前 64px 普通 Header 替换为 56px 上下文工具栏：

- 左侧：页面标题、面包屑、当前 Agent。
- 中间：全局命令搜索，可通过 `Command/Ctrl + K` 打开。
- 右侧：真实服务状态、当前租户、主题和用户菜单。

管理员身份不使用高刺激红色徽章。角色信息放入用户菜单和权限相关操作。DeepSeek、Ollama 和 MCP 的连接状态只有在读取到真实状态时才展示。

### 4.3 导航行为

- 当前模块使用玉青色边缘标记和表面层级表达。
- 折叠轨道中的图标必须有 Tooltip 和可访问名称。
- 展开和收起不会改变页面 URL 或当前焦点。
- 桌面路由切换使用 160-220ms 的淡入和轻微位移。
- 小屏幕下，品牌轨道、模块导航和检查器分别转为抽屉或底部 Sheet。

## 5. Assistant 主体验

### 5.1 消息层级

Assistant 使用三层叙事：用户意图、Agent 行为、最终结果与可执行操作。

用户消息使用紧凑的右侧容器。Agent 回复直接排版在主画布中，不把文本、推理、工具、来源和 A2UI 全部包装成同形卡片。

- 推理过程默认折叠为一行摘要。
- 知识来源显示为紧凑引用，选择后在检查器中展示原文与相关度。
- 工具调用显示为动作行，成功后收起为工具名、耗时和结果摘要。
- 图表、表单和 A2UI 可以突破文本列宽，但不得溢出主画布。
- 未知工具继续使用通用工具渲染器，保证历史兼容。

### 5.2 Assistant 空状态

首次进入显示简洁的品牌标识、能力说明和横向命令建议。空状态不使用三个相同功能卡片，不编造产品指标，不使用营销式口号。命令建议应对应真实黄金路径，例如知识库检索、数据分析、天气 MCP 和用户管理审批。

### 5.3 会话列表

- 按最近更新时间分组和排序。
- 显示会话标题、最近摘要、时间和活动工作流状态。
- 当前会话具有清晰的选中状态。
- 新建、选择和删除保留现有能力。
- 删除使用上下文确认，不使用浏览器原生弹窗。
- 不在本轮引入后端尚不支持的重命名、固定或批量操作。

## 6. 工作流体验

### 6.1 工作流轨迹

`data-workflow` 渲染为一条持续更新的纵向执行轨迹，而不是普通 Card。顶部展示目标、运行状态和真实完成比例。步骤直接使用任务标题，不添加无意义的“步骤 1”标签。

- 已完成步骤默认折叠，保留结果摘要。
- 当前步骤展开，展示输入、工具、执行状态和输出。
- 等待中的后续步骤降低视觉权重。
- 点击步骤在上下文检查器显示完整输入、输出、引用和执行记录。
- 完成后轨迹收敛为任务摘要，并保留“查看执行过程”。

### 6.2 中断与恢复

- `waiting_input`：根据真实工具 Schema 在当前步骤内渲染表单。
- `waiting_approval`：展示目标工具、参数、外部影响和批准或拒绝操作。
- `uncertain`：使用独立故障接管面板，提供确认完成、重新执行和取消剩余流程。
- `failed`：展示错误摘要、可恢复操作和诊断入口。
- `cancelled`：保留已经完成的步骤和取消位置。

活动工作流期间，普通聊天输入锁定。用户只可以提交缺失参数、批准、拒绝、取消或处理不确定状态。前端不发送合成确认文本，继续使用 AI SDK approval response 和现有工作流恢复接口。

### 6.3 输入台状态变形

普通状态下，输入台包含文本输入、附件、当前 Agent、可用工具提示以及发送或停止操作。活动工作流期间，它通过共享布局动画转为对应控制面板。

- 缺少参数：表单和“继续执行”。
- 等待审批：风险摘要、批准和拒绝。
- 执行中：当前动作和取消流程。
- 故障接管：确认完成、重新执行和取消剩余流程。

该区域始终是当前用户最需要采取行动的位置，避免同一状态在消息卡片、底部输入区和弹窗中重复出现。

## 7. 管理模块

### 7.1 知识库

- 顶部提供页面说明、搜索和上传主操作。
- 文档使用数据列表，显示类型、切片数、状态和更新时间。
- 上传采用侧边面板，包含文件、切片策略和参数。
- 上传中的文档行直接显示解析、切片和向量化进度。
- 文档检查器展示元数据和切片预览。
- 检索测试作为独立工作模式，查询结果与原文片段并排比较。
- 删除和重建索引使用上下文确认。

### 7.2 Skills

- 左侧按分类、权限和启用状态筛选。
- 主区使用有层级的能力列表，不使用相同的三列市场卡片。
- 检查器展示参数 Schema、示例结果、调用权限和测试入口。
- 测试结果在检查器原位置展开。
- 普通用户不显示其无权发现或调用的管理型 Skill。

### 7.3 MCP

- 顶部显示真实连接状态和可用工具数量。
- Server 使用连接列表，状态文本必须明确。
- 新增 Server 使用分步侧边面板。
- 展开 Server 后显示工具，选择工具后进入测试控制台。
- 外部调用明确说明数据将发送到哪个服务。
- 断开连接和删除配置是两个独立操作。

### 7.4 Agent 配置

页面采用双栏配置工作台。左侧按模型、行为、能力和外部连接组织编辑控件；右侧展示当前模型、已启用工具、Skills、MCP 和风险提示。

- System Prompt 使用适合长文本的编辑区。
- 只有存在未保存修改时，保存操作才获得主强调。
- 保存成功后展示修改摘要。
- 普通用户看到语义化只读内容，不显示一整页灰色 disabled 表单。
- “恢复服务器值”仅在存在本地修改时显示。

### 7.5 A2UI 实验室

页面采用三栏实验台：组件目录与模板、真实尺寸预览、Schema 编辑与校验。

- 预览可以切换桌面和移动端尺寸。
- Schema 错误定位到字段和行号。
- Assistant 中的 A2UI 部件可以跳转到实验室复现。
- 实验室和 Assistant 必须使用同一套真实渲染组件。

## 8. 主题系统

### 8.1 核心 Token

| 语义 | 深色主题 | 浅色主题 |
|---|---|---|
| 页面背景 | `#0B0F0E` | `#F3F7F5` |
| 主表面 | `#111715` | `#FCFEFD` |
| 抬升表面 | `#18201D` | `#FFFFFF` |
| 边框 | `#293530` | `#D7E1DD` |
| 主文本 | `#EDF4F1` | `#14201B` |
| 次文本 | `#9EADA7` | `#607069` |
| 品牌强调 | `#39D3A2` | `#087F5B` |
| 焦点环 | `#68E5BB` | `#0A9068` |

品牌色用于主操作、选中状态、焦点和工作流推进。黄色、红色和蓝色只用于真实警告、错误和信息状态。图表使用独立的数据可视化色板，不能将分类色复用为普通 UI 强调色。

### 8.2 形状与材质

- 面板圆角：16px。
- 输入框圆角：12px。
- 按钮圆角：10px。
- 状态标签：全圆角。
- 数据行优先使用留白和单一分隔线，而不是每行双边框。
- 玻璃材质只用于 Assistant 输入台和临时浮层。
- 减少透明效果或浏览器不支持时，玻璃材质退化为不透明抬升表面。

### 8.3 字体

- 中文正文：苹方、思源黑体与系统无衬线回退。
- 英文和数字：Geist Sans。
- Schema、ID、参数和日志：Geist Mono。
- 页面标题：24-28px。
- 正文：14-15px，默认行高约 1.6。

实现时使用 `next/font` 或本地字体，不通过生产页面外链加载字体。

## 9. 品牌标识与图标

品牌标识由两条开放的同心轨迹和一个中心节点构成。开放轨迹表达持续接收与思考，中心节点表达当前意图，轨迹方向可以对应工作流推进。

需要产出：

- 完整中文名称字标。
- 单独应用图标。
- favicon 与小尺寸单色版本。
- 深色和浅色主题版本。
- 登录和 Assistant 空状态的一次性轻动效版本。

系统操作图标统一使用 Phosphor Icons：

- 导航：20px Regular。
- 表单与行操作：18px Regular。
- 状态与工具：16px Regular。
- 空状态与模块标识：32px Regular。
- 只有选中和完成状态可以使用 Fill。

不混用 Lucide、自绘操作图标或 Emoji。品牌标识属于用户明确要求的定制品牌资产，不受操作图标禁止自绘规则限制。

## 10. 登录体验

登录页是品牌视觉最强的独立页面。桌面端左侧约 58% 展示“心流轨迹”视觉，右侧为窄幅登录面板。页面保持统一主题，不做明暗分裂。

- 抽象轨迹素材由 Canva 产出。
- 登录面板保留租户和演示账户提示，收纳到可展开区域。
- 字段错误显示在对应输入下方。
- 登录成功后，轨迹收束为应用导航标识。
- 减少动态效果模式使用静态轨迹图。
- 移动端移除大面积动态背景，仅保留品牌标识和低成本静态纹理。

## 11. 动效规范

| 类型 | 时长 | 用途 |
|---|---:|---|
| 即时反馈 | 100-140ms | 点击、开关、按压 |
| 组件切换 | 160-220ms | 抽屉、检查器、折叠 |
| 工作流变化 | 240-320ms | 步骤推进、审批转结果 |
| 页面进入 | 180-240ms | 路由内容显现 |

动效只使用 `transform` 和 `opacity`。持续值不得通过 React `useState` 在每帧更新。实现共享布局或复杂状态转换前必须检查项目依赖；若引入 Motion，应将动画隔离在 Client Component 叶节点中。

所有动效必须表达层级、反馈、进度或状态转换。禁止无语义无限循环，并完整支持 `prefers-reduced-motion`。

## 12. 响应式与移动端

- `>= 1280px`：完整四区布局。
- `768-1279px`：品牌轨道加主内容，其他区域使用抽屉。
- `< 768px`：顶部工具栏、主内容和全屏导航抽屉。

Assistant 输入台必须固定在移动设备安全区域内。会话、工作流详情和来源检查器转为底部 Sheet。管理列表转换为带字段标签的纵向记录，而不是压缩桌面表格。移动端不能通过隐藏控件减少功能范围。

## 13. 权限、错误和边界状态

所有页面必须覆盖以下状态：

- 匹配最终结构的骨架加载。
- 包含下一步操作的空状态。
- 行内错误与恢复操作。
- 网络断开与流式响应中断。
- 保存中、保存成功和保存失败。
- 只读与无权限。
- 长操作进度和取消反馈。
- 工作流等待、失败、不确定和取消。

RBAC 继续以服务端结果为准。UI 只负责正确呈现权限，不通过隐藏按钮代替服务端授权。跨租户资源不存在时仍按 404 处理，界面不泄露资源信息。

## 14. Canva 视觉交付物

在书面规格复核后，使用用户指定的 Canva 连接器制作以下内容：

1. 品牌情绪板与主题色板。
2. 品牌标识、应用图标和 favicon 方向。
3. 桌面端全局应用框架。
4. Assistant 空状态、普通对话和活动工作流三个关键画面。
5. 审批、缺参和 `uncertain` 三种中断状态。
6. 知识库、MCP、Agent 配置和 A2UI 实验室代表页面。
7. 登录页桌面与移动端画面。
8. 核心组件、图标、排版、间距和状态规范页。

Canva 稿用于确认视觉和交互，不作为代码中的像素截图直接嵌入。实现阶段仍使用真实组件、真实文本和真实应用状态。

## 15. 组件边界

实施时建议按以下边界组织：

- `AppShell`：品牌轨道、上下文工具栏和响应式区域。
- `PrimaryRail`：全局模块导航。
- `ContextPanel`：来源、工具、文档和配置详情的统一容器。
- `AssistantStage`：会话主画布和消息布局。
- `ComposerDock`：普通输入与工作流控制状态切换。
- `WorkflowTrack`：计划、步骤、中断和结果。
- `ResourceList`：知识库、Skills 和 MCP 的共享列表语法，不共享业务字段。
- `ThemeProvider`：主题选择、持久化和系统偏好。
- `BrandMark`：静态与一次性动效标识。

这些组件通过明确 Props 与现有 Store/API 通信。视觉组件不直接拼接后端 URL，不自行判断租户权限，也不复制工作流状态机。

## 16. 数据与交互流

### 16.1 Assistant

1. 会话 API 加载标准 `UIMessage.parts`。
2. AI SDK Transport 接收流式文本、reasoning、tool、approval、`data-a2ui` 和 `data-workflow`。
3. `AssistantStage` 根据 part 类型选择渲染器。
4. 点击来源、工具或步骤，将结构化对象交给 `ContextPanel`。
5. `ComposerDock` 根据活动工作流状态选择普通输入、表单、审批或故障接管控件。
6. 用户操作继续调用现有审批和工作流 API，不产生第二套前端状态机。

### 16.2 管理页面

1. 页面加载列表和当前权限。
2. 用户选择资源后打开检查器并加载详情。
3. 编辑操作保留在侧边面板或配置主区。
4. 保存成功后更新列表与详情缓存。
5. 保存失败保留用户输入并显示可恢复错误。

## 17. 测试与验收

### 17.1 视觉与响应式

- 深色与浅色主题覆盖全部页面。
- 390px、768px 和 1440px 三档截图回归。
- Assistant 空、对话、流式、工作流、审批和错误状态均有快照。
- 检查器打开和关闭时没有布局溢出或内容跳动。

### 17.2 交互与功能

- 登录、登出、租户展示和主题持久化。
- 新建、切换和删除会话。
- 工作流缺参、批准、拒绝、取消和不确定状态处理。
- 知识库上传、检索、删除和切片预览。
- MCP 连接、断开、工具测试与权限提示。
- Agent 配置编辑、保存、恢复和普通用户只读。
- A2UI Schema 预览和错误定位。

### 17.3 可访问性与性能

- 键盘可以完成登录、导航、对话、审批和配置保存。
- 文本、输入、按钮和焦点环达到 WCAG AA。
- 所有图标按钮具有可访问名称。
- `prefers-reduced-motion` 下无持续动画。
- 页面切换和工作流更新不造成明显 CLS。
- Lighthouse 性能和可访问性不因视觉升级明显下降。

## 18. 非目标
