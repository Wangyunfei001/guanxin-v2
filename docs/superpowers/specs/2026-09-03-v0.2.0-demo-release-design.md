# 观心 v2 `v0.2.0-demo` 封版设计

> 日期：2026-09-03  
> 状态：已确认，待实施验收

## 1. 目标

把当前本地稳定 Demo 收口为可重复验收、可通过 GitHub CI 守护、可由外部 MCP 客户端调用并可正式发布的 `v0.2.0-demo`。本轮补齐原 PRD 中“外部客户端调用观心知识库与 Skill”的 P0 能力，同时保持现有 FastAPI、租户隔离和 RBAC 为唯一业务授权边界。

本轮不引入生产部署、审计日志、限流、远程 MCP、账号数据库迁移、条件工作流或并行 DAG。

## 2. 观心 MCP 网关

新增独立 stdio MCP Server。它是现有 HTTP API 的薄适配层，不直接访问 SQLite、ChromaDB 或 Skill 内部实现。

启动配置：

- `GUANXIN_API_BASE_URL`：默认 `http://127.0.0.1:8000/api`。
- `GUANXIN_API_KEY`：必填，通过 `X-API-Key` 请求头传给 FastAPI，不记录在日志或错误中。

固定暴露三个只读工具：

| 工具 | 输入 | 后端调用 |
|---|---|---|
| `knowledge_retrieve` | `query: string`, `top_k: integer = 5` | `POST /knowledge/retrieve` |
| `text_summary` | `text: string`, `max_sentences: integer = 3` | `POST /skills/execute`，固定 `skill_name=text_summary` |
| `data_analysis` | `data: number[]`, `analysis_type: basic\|full = basic` | `POST /skills/execute`，固定 `skill_name=data_analysis` |

网关不提供通用 `execute_skill`，因此外部客户端无法借此发现或执行写 Skill。API Key 对应用户的租户与角色仍由 FastAPI 验证。缺少密钥时进程在进入 stdio 会话前失败；连接失败、超时、HTTP 非成功状态、业务非零状态码和异常响应统一转换为 MCP tool error。

`scripts/start-mcp-server.sh` 改为启动观心网关；天气示例迁移到 `scripts/start-weather-mcp-server.sh`。前者表示“外部客户端调用观心”，后者表示“观心调用外部天气工具”。

## 3. 测试隔离与门禁

MCP 测试分两层：HTTP 适配器单测覆盖输入、认证和错误映射；协议测试使用独立进程完成 MCP initialize、工具发现及三个工具调用。两层测试都只访问本地测试服务。

Playwright 覆盖登录/租户隔离、知识库上传与检索、Skill/A2UI、工作流审批与刷新恢复。所有数据库、checkpoint、Chroma、上传和用户 JSON 数据都放在单次运行的系统临时目录中，结束后精确清理。

新增 `USER_DATA_PATH` 配置，默认值仍指向现有 `backend/data/users.json`。测试环境必须显式覆盖它，从而允许工作流真正执行创建用户而不污染演示数据。

GitHub Actions 在 pull request 和 `main` push 上执行后端 pytest、前端 lint/typecheck/build、Playwright 和 MCP 协议测试。CI 不配置真实模型或公网服务密钥。

## 4. 真实验收

真实验收使用独立临时数据目录，但连接当前配置的 DeepSeek、Ollama `bge-m3:latest` 与公网。发布前必须通过：

1. PDF 上传、检索、Agent 引用回答。
2. Data Analysis Skill 与 A2UI 图表。
3. Agent 调用真实 Open-Meteo 天气 MCP。
4. 独立 MCP SDK 客户端发现并调用观心的三个工具。
5. Quick Research 与 Deep Research 各一次。
6. 工作流补参、审批、完成、刷新与后端重启恢复。
7. tenant-a 与 tenant-b 数据隔离。

第三方临时故障可以重试，但任何必选场景失败都阻止发布。验收报告只记录脱敏输入输出、环境版本和结果，不提交 API Key。

## 5. 文档与发布

README 区分两类 MCP Server，并提供 API Key 获取、客户端配置、验证命令和故障排查。PRD 更新为 React/Next.js 现状，删除过期 Draft 表述，并明确已交付和延期范围。新增 Demo 操作手册、验收报告及 release notes。

前后端包元数据和健康接口统一为 `0.2.0`。实现通过 `release/v0.2.0-demo` 分支提交 PR；全量 CI 与真实验收通过后 squash merge 到 `main`，在合并提交创建 annotated tag `v0.2.0-demo`，并创建不含二进制附件的 GitHub Release。

## 6. 退出条件

- 全部自动化测试和真实验收通过。
- 外部客户端只能发现三个计划内只读工具，并遵守 API Key 与租户隔离。
- 测试不在仓库数据目录留下运行产物。
- README、PRD、版本、脚本和实际行为一致。
- GitHub `main`、标签与 Release 指向同一已验证提交。
