# MCP Agent 启用与工具查询修复规格

> 日期：2026-08-25
>
> 状态：待书面确认
>
> 范围：MCP 连接后的租户 Agent 启用、工具查询意图、内部分类事件隔离

## 1. 问题与目标

当前 MCP Server 的“运行时已连接”和“当前租户 Agent 已启用”是两个独立状态。管理员连接天气 Server 后，当前租户的 Agent 配置仍可能保持 `mcp_servers=[]`，导致模型看不到天气工具。与此同时，意图分类器的内部输出会被通用模型流监听器当作回答文本发送，页面因此出现 `knowledge_query`。

本次修复目标是：管理员连接 MCP 成功后，下一轮对话即可直接使用该 Server；MCP 页面能够区分运行连接与 Agent 启用状态；天气等外部工具请求稳定进入工具执行链路；内部意图标签不再进入用户可见文本或历史消息。

## 2. 方案比较

### 方案 A：后端连接成功后自动启用，并展示双状态（采用）

`POST /api/mcp/connect` 在 Server 连接成功并发现工具后，将 Server 名称幂等追加到当前租户默认 Agent 配置。MCP 页面读取 Agent 配置，分别展示“已连接”和“Agent 已启用”。该方案把连接与启用收敛为一次管理员操作，并由后端保证租户边界。

### 方案 B：前端串联连接与配置保存

页面先连接 Server，再读取并保存 Agent 配置。改动集中在前端，但两个请求之间可能出现连接成功、配置保存失败的半成功状态，也容易被其他客户端绕过。

### 方案 C：仅增加提示，继续要求手工启用

改动最小，但保留了重复操作和误解来源，不符合“连接后即可在 Assistant 使用”的演示目标。

## 3. 后端设计

### 3.1 MCP 连接与租户配置

- 只有管理员可以连接 Server，沿用现有 RBAC。
- MCP 客户端返回 `status=connected` 后，读取当前用户 `tenant_id` 的默认 Agent 配置。
- 若 Server 尚未启用，则追加到 `mcp_servers` 并保存；已存在时不重复写入。
- 连接失败时不修改 Agent 配置。
- 连接响应保留现有字段，并增加 `agent_enabled: true`，供页面即时更新提示。
- 不改变普通用户修改 Agent 配置的权限，也不自动启用其他租户。

### 3.2 工具查询意图

- 在 `IntentEnum` 中新增 `tool_query`，模式映射为 `direct`。
- 为天气、气温、温度、下雨、降雨、空气质量等常见天气表达增加高优先级正则，直接分类为 `tool_query`。
- LLM fallback 的可选标签增加 `tool_query`，用于其他 MCP 或外部工具请求。
- `tool_query` 只负责进入 ReAct 工具链；可用工具仍由当前租户持久化 Agent 配置和运行连接共同过滤，不绕过权限。

### 3.3 流式事件隔离

- 继续通过独立 `intent` SSE 事件传递结构化分类结果。
- `on_chat_model_stream` 事件若来自 `intent_parser` 节点，则不发送 `token`、不追加到 `full_response`。
- `chat_responder` 和 `react_executor` 的用户可见模型输出保持现有流式行为。
- 历史消息只保存用户可见回答，因此不会再持久化 `knowledge_query` 等内部标签。

## 4. 前端交互

- MCP 页面加载 Server 和运行连接时，同时读取当前租户 Agent 配置。
- 每个 Server 独立展示运行连接与 Agent 启用状态：连接成功后显示“已连接”和“Agent 已启用”；历史遗留状态显示“已连接但未启用”。
- 连接成功提示改为“连接成功，已为当前 Agent 启用，发现 N 个工具”。
- 页面说明明确：连接成功后，工具会在下一轮 Assistant 对话中生效。
- 本轮不增加断开接口，也不改变 Agent 配置页现有的手工启用与停用能力。

## 5. 错误处理与兼容性

- MCP 连接成功但 Agent 配置保存异常时，请求返回失败，不宣称已启用；已经建立的进程连接可以保留，页面刷新后会显示真实双状态。
- 现有 MCP 连接响应字段保持不变，新增字段为向后兼容扩展。
- 已有租户配置不做批量迁移；管理员重新连接 Server，或在 Agent 配置页保存，即可消除历史遗留状态。
- 内置天气 Server 仍返回模拟数据，页面和 Assistant 不将其描述为实时天气。

## 6. 测试与验收

- API：连接成功后只为当前租户启用对应 Server；重复连接不产生重复配置；连接失败不修改配置；普通用户连接返回 403。
- 意图：典型天气问句命中 `tool_query`；普通知识问题仍命中 `knowledge_query`；未知语句的 LLM fallback 可返回 `tool_query`。
- 流式：来自 `intent_parser` 的 token 被过滤；来自回答节点的 token 正常发送并持久化。
- 前端：TypeScript、lint 和 build 通过；MCP 页面能区分“已连接”“Agent 已启用”“已连接但未启用”。
- 黄金路径：管理员连接天气 MCP 后，无需再进入 Agent 配置页保存；新一轮询问北京天气时产生 `mcp__weather__get_weather` 工具调用，回答正文不含 `knowledge_query`。
