## 验收中发现并修复的问题

- PDF 原先未真正解析，补充 PDF/DOCX 文本提取及上传回归测试；扫描 PDF 不支持 OCR。
- 文档详情补全前端已使用的 chunks 数据，修复切片预览；未增加 HTTP 路由或改变已有认证/租户边界。MCP 网关仅调用既有 HTTP API。
- A2UI 适配 `skill__*` 工具名和 JSON 包裹的检索结果，修复图表及引用渲染。
- Research 数据块使用稳定 run ID，避免流式阶段产生重复卡片；provider 单次请求设 60 秒硬截止，失败明确标记 failed，不冒充完整报告。
- Next.js 原始代理超时为 30 秒，已提高至 600 秒以覆盖 Deep 的 480 秒预算；正常重验请求经过代理完成。
- MCP launcher 的诊断日志改走 stderr，防止污染 stdio 协议。
- 首轮全新 CI 安装了不兼容的 MCP SDK 2.1.1（原依赖没有主版本上限），导致三个协议测试失败；封版固定为真实验收使用的 1.28.1，避免全新安装漂移。
- npm 下载地址统一到官方 registry，迁移时保持版本与 integrity 不变；随后将直接 nanoid 依赖单独固定为支持 Node 20 的 5.1.16（此前 6.0.0 声明仅支持 Node 22+）。CI 安装请求 60 秒超时，各任务 15 分钟上限；未放宽任何测试门禁。
- E2E 使用独立端口/构建目录，修复冷编译等待、开发指示器遮挡及会话 ID 清理问题；pytest 的 users JSON 也纳入临时目录。

## 发布门禁与边界

本地与真实验收完成不等于已发布。PR 全量 CI、squash 合并提交的 main CI、annotated tag 与 GitHub Release 必须继续核对；这些外部结果在 PR/Release 中记录。版本在提交 PR 前统一，避免合并后再改版本造成标签与已验证提交不一致。

本轮不交付审计日志、限流、远程 MCP、生产部署、账号数据库迁移、条件分支或并行 DAG。登录账号/API Key 是进程内预设；管理型 Skill 的 JSON 记录不等于认证账号。真实服务可能临时不可用，演示失败时需排查并重试，不能将超时的部分报告作为完整成功。
