# 2026-09-09 真实模型评估与旧研究清理

结论：原生 Agent 能完成知识回答、报告落盘和审批前等待；网页研究仍需逐条审查引用，暂不扩大无人审核的研究输出范围。已建立可复跑评估并删除旧研究执行循环。

## 环境与方法

三个批次、每批四类固定合成任务，共 12 次任务运行。真实 DeepSeek API、真实 Deep Agents、真实 Embedding/Chroma 检索；业务库、文件与向量库全部隔离，未接受任何写操作审批。主模型请求和回包均为 `deepseek-v4-pro`，搜索模型为 `deepseek-v4-flash`。连接探针发现 `.env` 的 `deepseek-chat` 别名实际返回 Flash；未修改用户已有模型配置。

四类用例分别验证：从单篇测试知识文档提取三个事实；查询 LangGraph 官方文档；依据明确标注的合成资料生成 Markdown；新增用户请求建立审批但不执行。知识库测试只有一个文档，不能证明多文档排序质量；审批为单步确定性业务流程，不代表复杂规划正确率。

每个任务保留 JSON：答案、工具证据、文件、模型 token、搜索 token、耗时、机械检查。未使用 LLM-as-judge 或上传 LangSmith。机械检查是关键字、调用、文件和链接来源检查，不能作为语义准确率。

## 人工引用审查

- **知识库**：5 个工作日、项目负责人签字、2 个工作日内复测，均与合成知识文档原文一致，文件名明确。通过当前窄任务。
- **报告**：最终文件存在，三个事实与输入相符；两个 example.com URL 是用户提供的评估标识，不是真实网页证据。报告明确说明未经联网核实，通过这项边界检查。
- **研究第 1 项：部分支持。** 回答将持久化笼统等同于 checkpointer，遗漏 Store。当前 [Persistence 原文](https://docs.langchain.com/oss/python/langgraph/persistence) 区分线程图状态（checkpointer）与跨线程应用数据（Store）；Agent Server 自动提供这些能力。正确表述应限定为“保存/恢复线程图状态需要 checkpointer”。最终答案提及 Agent Server，但仍有概括过度。
- **研究第 2 项：基本含义支持，直接引用未完成独立核验。** thread_id 用于标识/恢复线程，checkpoint_id 用于某个检查点，不应把 thread_id 说成每个检查点自身的唯一 ID。[Interrupts 原文](https://docs.langchain.com/oss/python/langgraph/interrupts) 支持线程恢复的基本含义。模型引用的 Checkpointers 页面本次独立读取失败，不能将网络读取失败等同于 URL 无效，也不能据此判为已核验。
- **研究第 3 项：Python 结论支持。** 同一 thread_id 与 `Command(resume=...)`、恢复后节点从头执行均得到 [Interrupts 原文](https://docs.langchain.com/oss/python/langgraph/interrupts) 支持；额外 JS 示例未单独核验。
- **来源可信度**：最终搜索结果全部是从模型正文抽取的 URL，没有结构化 citation annotation。因此即便全部链接可在工具返回中找到，也不构成独立网页证据验证。代码将其标记为 `model_text_unverified`，自动检查不输出“引用准确率 100%”。
- **审批**：无写入，未声称创建成功。虽然用户名/邮箱已在请求中，现有确定性业务规则仍要求表单确认，这是体验改进项，不是模型越权。

## 清理结果与兼容

本机旧 research_runs 清点为 0 条。删除旧研究 engine、专用 plan/find_gaps/synthesize、规划模型、无引用任务写入方法与旧预算配置；工具目录不再发布无运行实现的 deep_research 工具。已有配置中的旧字段仍可读取，数据库表与历史报告不删除。

旧 `resume` 将目标、报告、来源、任务作为不可信上下文转入原生任务，并用稳定请求 ID 去重。原记录保留并标明迁移；这不是精确恢复旧循环。租户/用户、当前任务互斥和业务审批锁仍由服务端检查。前端按钮显示“用新任务继续”，操作失败有提示。
