# 观心 v2 目标与需求

## 目标

观心 v2 是一套**可稳定演示的多租户 AI Agent 全栈基线**：本地一条命令起服务，就能完整演示「上传文档 → 检索 → Agent 规划与调用工具 → 需要写操作时进入审批 → 产出可下载文件 / 可核查引用」的闭环，并且同一套行为可被自动化测试与浏览器回归重复验证。

它服务于两类观看者：内部技术团队（验证 Agent 运行时、MCP、Skill、A2UI 等模块能否真正串起来），外部合作方（能力展示、技术选型参考）。

## 问题

把 Agent 能力讲清楚，需要同时证明四件事：模型真的能选对工具、权限真的在服务端收口、写操作真的经过人、结果真的可复查。任何一环靠演示脚本伪造，整套系统就失去参考价值。

## 使用者的核心场景

- **技术同事**：读一遍规格与架构就知道边界在哪，改一个模块不会踩坏另一条链路；跑 `pytest` 与 `playwright` 就能确认没退化。
- **演示者**：用预设账号登录不同租户，演示知识库问答、只读工具、审批型写操作、研究报告与引用审查，中途刷新或重启服务后仍能继续。
- **外部客户端**：通过观心 MCP 网关用 API Key 调用三个只读工具，或在 Claude Desktop 里接入。

## 能力

（均为当前代码已实现的能力。）

- **身份与租户**：JWT / API Key 双认证，预设 Demo 账号分属两个租户，所有业务数据按 `tenant_id`（会话、工作流、研究再叠加 `user_id`）隔离，越权统一 404。
- **知识库**：PDF 文本层 / DOCX / TXT 上传解析、分块、Ollama `bge-m3` 向量写入 ChromaDB、按租户 collection 检索，文档状态全程可追踪，失败有补偿。
- **Agent 运行**：Deep Agents 官方工具循环 + LangGraph SQLite checkpoint，原生流式事件、可重放订阅、刷新或重启后从 checkpoint 继续；虚拟文件只存在于会话状态内，可下载 Markdown 报告。
- **工具授权**：工具目录按租户 Agent 配置、RBAC、MCP 风险标注构造，可见性与风险等级由 Agent 与工作流共用同一份判定；只读工具自动执行，写与未知风险工具只能进入可审批的持久化工作流。
- **持久化工作流**：DeepSeek Planner 生成最多 16 步线性计划，LangGraph `interrupt()` 暂停等待参数或审批，幂等执行、可取消、进程异常窗口内的风险步骤交由 admin 接管。
- **联网研究**：授权工具 + DeepSeek Web Search，会话级搜索预算，仅从可信域名读取原文并与逐字摘录比对，引用一律待人工审查。
- **MCP 双向**：观心 Agent 消费 stdio MCP Server（含真实天气 Server），观心自身也作为只读 MCP 网关供外部客户端调用。
- **Skill 与 A2UI**：内置文本摘要、数据分析与管理型 Skill；五类声明式 UI 卡片由 Agent 返回、前端渲染，卡片交互回传后端。
- **前端工作台**：会话列表 / 流式回答 / 工具结果 / 审批与参数表单 / 研究来源 / 用户统计看板，另有知识库、Skills、MCP、Agent 配置、A2UI 五个管理页。

## 非目标

以下为明确排除，而非尚未想到：

- 生产部署形态：高可用、横向扩展、分布式锁、多进程 worker 调度。后端固定单进程 Uvicorn，ChromaDB 与 checkpoint 都在本机。
- 账号体系生产化：登录账号与 API Key 是进程内预设数据，不迁移为账号数据库。
- 审计日志、限流、计费护栏；搜索预算只约束本产品发起的搜索请求，不是账户级费用上限。
- 远程 MCP SSE / 云端 MCP；当前只做本地 stdio。
- 条件分支、并行 DAG、跨机器执行的流程编排；工作流只支持线性计划。
- 扫描件 OCR；PDF 只取文本层。
- 语义级事实判定：引用工具只做逐字匹配，「摘录存在」不推出「主张成立」。
- 会话附件里的图片 / PDF、checkpoint 时间旅行与分支编辑。

## 原则

- **服务端是唯一授权边界**：客户端不能指定 tenant、user、model 或工具权限；每次工具调用、每次工作流恢复都重新校验。
- **不重写官方已经给的能力**：消息拼装、运行状态机、工具循环交给 LangChain / Deep Agents 官方实现，本仓库只做业务投影。
- **写操作只有一条路**：Agent 调 `request_business_workflow` → 进入持久化工作流 → 人工审批 → 幂等执行；不给通用 Agent 直接写权限，也没有绕过模型的正则旁路。
- **演示必须真实**：模型或 Embedding 不可用时明确报错并留痕，不返回伪造的成功结果，也不用随机向量代替语义检索。
- **本地数据优先**：SQLite + ChromaDB + 本地 Ollama，零外部部署依赖，便于一键起停与清理。
